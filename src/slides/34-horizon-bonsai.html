Sixteen bits per weight, exactly as the training run left it. Nothing on this slide is smarter than this row — it is only bigger.

16 GB laptop 8 GB laptop A phone

Bonsai (PrismML, Apache 2.0) is trained with {−1, 0, +1} weights from the start — never a 16‑bit model that got rounded, so there is nothing to lose on the way down: 8 B in 2.2 GB, benchmark average 75.5 against 70.5 for the earlier 1‑bit version that had no zero. Three values is 1.58 bits in principle; the shipped format spends 2.125, because every group of 128 weights carries a 16‑bit scale — the same block cost as §4, one section later. The catch is which build you grab. The 1‑bit files (*-Q1_0.gguf) are merged upstream and run on any recent llama.cpp. Ternary (*-Q2_0.gguf) does not: it still needs PrismML’s own fork, and that fork is CPU and Metal only — no CUDA, no Vulkan — with the upstream patch still pending. This has moved three times in a year; check the machine you are presenting from, on the night. The decode figure is §3’s formula on a published bandwidth, so it is a ceiling: PrismML measure 82 tok/s on an M4 Pro against the 124 this slide predicts, which is the usual two thirds.
